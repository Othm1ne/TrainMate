# TrainMate

Meet your sport mate through our app.

TrainMate is a Flutter app for finding training partners nearby: swipe through
people who share your sports, match, chat, and join local sport events.

## Features

- **Auth** – email/password (with password reset), Google, Apple (iOS/macOS/web)
- **Profile** – photo, level, age, sports, bio, auto-detected location, badges,
  completion score; view other users' profiles
- **Find a partner** – swipe deck of people who share your sports, sorted by
  distance, with filters (sport, level, distance); mutual likes create a match
- **Chat** – real-time messages with your matches; mute, block/unblock, report
- **Events** – create events (cover photo, category, place, date), join/leave,
  see attendees and distance, "Going" filter, delete your own events
- **Premium** – unlimited likes (free: 20/day) and "See who liked you"
- **Push notifications** – new match and new message (Android/iOS)
- **Store** – sell and rent out sports equipment: listings with photos,
  search and filters, rental requests with an availability calendar,
  handover/return photos, reviews, verified renters-out (email + phone SMS),
  pro shops, boosts. Spec: `docs/specs/store-sell-and-rent.md`

## Stack

Flutter · Firebase Auth · Cloud Firestore · Firebase Storage · Cloud Functions (TypeScript) · FCM · geolocator/geocoding

```
lib/
  main.dart                 Firebase init
  firebase_options.dart     generated by `flutterfire configure`
  src/
    app.dart                MaterialApp + AuthGate (onboarding / complete profile / app)
    data/models/            UserProfile, EventItem, ChatThread, Message
    data/services/          auth, users, matches, chats, events, storage, location
    features/               one folder per screen group (auth, home, chat, events, profile, premium)
    shell/main_shell.dart   bottom navigation
    shared/                 sports list, shared widgets
functions/src/
  matching.ts               swipe (likes, daily limit, match → chat), activatePremium
  chat.ts                   push notification on new message
  notify.ts                 FCM helper (cleans up dead tokens)
```

Likes, matches and Premium go through Cloud Functions so the daily limit
and match creation can't be faked from a modified client.

## Setup

1. Install Flutter (3.32+) and the Firebase CLI (`npm i -g firebase-tools`).
2. Create a Firebase project and enable:
   - **Authentication** → Email/Password, Google (and Apple if you ship on iOS)
   - **Cloud Firestore**
   - **Storage**
3. Connect the app (this overwrites `lib/firebase_options.dart`):
   ```bash
   firebase login
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
4. Deploy the backend (Cloud Functions need the Blaze plan):
   ```bash
   firebase use <your-project-id>
   cd functions && npm install && cd ..
   firebase deploy --only firestore,storage,functions
   ```
5. Run:
   ```bash
   flutter pub get
   flutter run
   ```

### Google Sign-In

- **Android**: add your SHA-1 (`cd android && ./gradlew signingReport`) in the
  Firebase console → Project settings → Android app, then re-run `flutterfire configure`.
- **iOS**: add the `REVERSED_CLIENT_ID` from `GoogleService-Info.plist` as a URL
  scheme in `ios/Runner/Info.plist`.

## Store administration (Firebase console → Firestore)

There is no admin app yet; these are done by editing documents:

| Task | How |
|---|---|
| Approve a pro shop | `shops/{id}` → set `status` to `approved` (or `rejected` / `suspended`). Owner and listings update automatically and the owner gets a push |
| Review a held listing | `listings/{id}` with `status == pending_review` → set `status` to `active` or `removed` (`moderationFlags` says why it was held) |
| Handle a dispute | `bookings/{id}` with `status == disputed` → contact both users, then set `status` to `resolved` |
| Suspend someone from the store | `users/{uid}` → `storeSuspended: true` |
| Reports | `reports` collection (`type`: listing / booking / user) |

Phone verification needs **Authentication → Sign-in method → Phone** enabled
(add test numbers there for development).

## Data model (Firestore)

| Path | Content |
|---|---|
| `users/{uid}` | profile, `lat`/`lng`, `blocked[]`, `isPremium`, daily like counter |
| `users/{uid}/swipes/{otherUid}` | `{from, to, liked, at}` (written by the `swipe` function) |
| `users/{uid}/devices/{token}` | FCM tokens for push notifications |
| `chats/{uidA_uidB}` | `members`, `memberInfo`, `lastMessage`, `mutedBy`, `blockedBy` |
| `chats/{id}/messages/{id}` | `{senderId, text, sentAt}` |
| `events/{id}` | event details, `creatorId`, `attendeeIds[]`, `attendeePhotos{}` |
| `reports/{id}` | user reports for moderation |
| `listings/{id}` (+ `blocked/{day}`) | store listings; booked days per listing |
| `bookings/{id}` | rentals and their status history |
| `sales/{id}`, `reviews/{id}`, `shops/{id}` | sales, two-sided reviews, pro shops |

## Known limitations

- Premium has no payment provider yet: the `activatePremium` function grants
  it to anyone who asks. Add App Store / Play / Stripe receipt verification
  there before release.
- Push notifications are not set up on web (needs a VAPID key + service
  worker). On iOS, upload an APNs key in Firebase → Project settings → Cloud
  Messaging and enable the Push Notifications capability in Xcode.
- Locations are stored rounded to ~1 km because profiles are readable by all
  signed-in users.
